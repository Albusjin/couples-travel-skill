# 接收方 Agent：安装、配置与使用规范

适用版本 **1.2.1**，维护于 2026-11-03。本文写给执行安装的 agent：用户把本目录交给你并要求安装时，完成必要且获授权的检查、配置和验收，不只给用户一串命令。遇到缺失信息时继续独立工作，集中收集真正无法推断的输入。

## 1. 识别目录与授权范围

- 独立 ZIP 解压后：`travel-planner/` 就是 Skill 根目录，包含 `SKILL.md`、`VERSION`、本文、`scripts/`、`config/`、`references/` 和 `MANIFEST.json`。
- 完整仓库下载后：Skill 根目录为 `skills/travel-planner/`，仓库还有测试和打包器。不要把整个仓库安装成一个 Skill。
- 安装授权涵盖本 Skill 所需的隔离安装、必要依赖和选定服务配置，不自动授权交易、公开上传行程、覆盖其他应用设置或改动既有旅行。
- 当前只保留网站功能基础，视觉设计尚未定稿；安装阶段不生成、不设计、不发布旅行网站。

以下命令从 **Skill 根目录**执行，`python3` 表示你实际验证过的 Python 3.11+。Windows 可使用 `py -3` 或解释器绝对路径；不要机械照抄系统名称或占位路径。

## 2. 预检：先复用，再补齐

自行确认操作系统、当前执行位置、宿主名称/版本、文件与命令权限、可用 Python、已安装依赖、内存压力和可用磁盘；只有选择本地铁路服务时才检查 Node/npm。按实际宿主决定如何发现 Skill，不假设任何能聊天的应用都能执行脚本或 MCP。

只做小范围检查，不打印整份环境、宿主配置、凭证文件或命令历史。不要为安装 Skill 另外下载模型、Docker、浏览器或完整开发工具链；串行处理，不启后台轮询。优先复用现有合适 Python/虚拟环境，避免重复安装依赖。

必要时向用户收集：

1. 无法判断时，目标 agent 应用/宿主。
2. 需要保存真实资料时，用户认可的、安装包与 Git 仓库外的私有持久目录。
3. 用户希望启用的实时服务，以及缺少的本地授权。

有依据能自动完成的检查不反复询问。远程容器或远程服务器的文件系统不等于用户电脑；未确认私有性和持久化时先做不保存的讨论。

## 3. 检查包与选择安装位置

新解压 ZIP 先运行：

```sh
python3 scripts/verify_package.py
```

确认 `ok=true`、版本 1.2.1、校验文件数合理。源码目录没有生成的 `MANIFEST.json` 时，按 Git 来源/发行 ZIP 核对，不伪造文件使校验通过。校验值仅证明与所带清单一致，不是签名或信任证明；有异常停止执行该包，重新获取可信副本。

推荐目标由宿主决定：

| 宿主 | 常用发现目录 | 注意 |
| --- | --- | --- |
| Codex | `~/.agents/skills/travel-planner` | 检查本机会话实际发现状态，支持软链接但分享默认完整复制 |
| DeepSeek Harness | `~/.dsh/skills/travel-planner`，默认也扫描用户 `.agents/skills` | 自定义 profile 可关闭默认根，按实际设置确认 |
| 其他 | 宿主官方 Skill 目录或显式加载路径 | 不把 Codex TOML/DSH YAML 当通用语法 |

完整复制安装：

```sh
python3 scripts/install.py --destination "<已确定的目标绝对路径>"
```

安装器拒绝已有目标，不自动覆盖。遇到同名安装先比较版本和用户目标；已授权升级时先在发现目录之外保留旧版，再安装/验收并切换；未授权替换时说明具体冲突。已有软链接不得跟随写坏它的源目录。不要让多个同名副本同时被宿主扫描，也不要删除其真实数据或已配置环境。

复制完成后，**切换到安装后的目录继续配置**，不再配置将被清理的解压临时目录。若用户本来就在已安装目录且版本正确，直接验收，不重复复制自己。

## 4. 配置运行环境与数据目录

读取 `config/runtime.local.example.toml`，在安装目录创建目标机自己的 `config/runtime.local.toml`，仅写路径/运行选项，不写 Key。至少将 `paths.data_dir` 指向用户认可的私有存储；必要时指定 `executables.python` 和可复用的 `paths.venv_dir`。Windows TOML 路径可用正斜杠或单引号字面字符串。

数据路径不能在安装包或 Git 仓库内，不使用发布者默认路径，不复制其他人的偏好、订单或演示资料。目录未确认前不初始化真实旅行；离线示例和讨论可以继续。已有私有目录不要清空，也不要直接改 HEAD/历史修订。

先检查：

```sh
python3 scripts/runtime.py doctor --core-only
```

核心必须满足 Python 3.11+、`jsonschema` 和可用的 `Asia/Shanghai` 时区数据。Node/npm/专用虚拟环境在 `--core-only` 下不是必需；检查输出的 `checks.*.required` 和 `ok`，不要因为可选项缺失宣称核心失败。

只有缺少依赖时才执行：

```sh
python3 scripts/runtime.py bootstrap --core-only
python3 scripts/runtime.py doctor --core-only
```

该入口只在配置的 venv 安装核心依赖；已就绪不重复 bootstrap。额外的 `requirements-amap-setup.txt` 仅在确实使用 Codex 配置辅助或需要完整开发测试时安装，不为三个 HTTP 服务默认安装本地 Node 服务。

## 5. 完成离线验收

```sh
python3 scripts/runtime.py run validate --input examples/demo-trip.json
python3 scripts/runtime.py run budget-fit --input examples/demo-trip.json
```

两条命令都不创建真实旅行。检查 JSON：`validate` 的 `result.errors` 应为空，按数据实际状态解释 `can_confirm`、warnings/pending；预算 `allocation.status=allocated` 只表示额度数学上可分配，不证明报价/库存核实。

再用有效解释器运行完整 mock 演示：

```sh
python3 examples/walkthrough.py --data-dir "<新建的仓库外临时验收目录>"
```

如果依赖装在 venv，使用 doctor 返回的 `venv_python` 运行示例；该脚本不经过 runtime 自动选解释器。验收应包含候选、选择、详细规划、模拟确认/锁定、第二天局部修改及同修订的三份 Markdown。模拟确认不能替代实际用户授权，不把 `mock` 改成 `real`。只清理本次创建的临时验收目录。

安装后的包内资源必须可独立读取，不能依赖解压来源、发布者电脑或开发仓库。没有可执行环境时报告限制，不声称本地安装完成。

## 6. 连接所需实时服务

先读 [跨宿主配置](references/harness-setup.md)，再选择对应参考模板：

- Codex：`config/mcp-codex.example.toml`，四项默认 `enabled=false`。
- DeepSeek Harness：`config/mcp-deepseek.example.cordis.yml`，四项默认 `disabled=true`。
- 其他宿主：根据其当前官方机制转换，复用已有连接，不替换宿主。

选定服务逐项处理，用户没要求的服务保持停用。已有同身份且获授权连接可直接复用，不为统一名字重装；缺一项不阻塞其他能力。

| 服务 | 用途 | 准备条件 |
| --- | --- | --- |
| 高德 | 地点搜索、详情、路线、覆盖日期内天气 | 官方 MCP 接入与目标机 Key/已有授权连接 |
| 铁路 | 站码、直达/中转、目标日或参考日列车 | 社区固定版本 `12306-mcp@0.3.10`、适用 Node/npm 与网络；无需铁路密码或证件 |
| 酒店 | RollingGo 标签、搜索和具体房型详情 | 官方端点、接收方授权；实际房型/房期/税费与退改另核实 |
| 滴滴 | 上下车点检索和一车价格预估 | 官方 MCP 接入与授权；只允许地点搜索和预估 |

配置前备份，只合并选定服务项，保留模型、其他 MCP 和权限。真实 Key 仅通过本地凭证界面、隐藏输入或宿主进程环境设置；不让用户在聊天粘贴，不输出带 Key URL、Authorization 或完整环境。模型 Key 与旅游服务 Key 分开，不随包共享。替代服务先核验来源与字段，失败不自动换陌生代理或 `latest`。

只读工具范围见 `config/mcp-routing.toml`。Codex 保留 `enabled_tools`；其他宿主按实际工具权限机制限制，不添加不支持的兼容字段。DSH 示例本身不执行白名单过滤；尤其滴滴不能验证查询权限隔离时保持停用，说明打车预估暂缺。任何宿主都不调用发单、支付、取消、司机位置或订单操作。

`runtime.py mcp-config` 仅生成 Codex 高德/铁路配置；`setup-amap --apply` 只用于已选定的 Codex 高德配置，不用于 DSH/其他宿主，也不是四服务自动安装器。检查环境时不运行会写配置的双击启动器。Windows 的 stdio 用目标机真实 `node.exe`/`npx-cli.js` 路径和独立参数，不能复制别人的 macOS 路径。

## 7. 分层验收与交付报告

所选连接重载后，在当前会话发现实际工具和输入 schema，再按 [MCP 验收](references/mcp-setup.md) 做少量匿名、只读业务检查。一个服务一次小查询链即可，不循环探测；瞬时网络最多重试一次，鉴权或配额问题交给用户处理。

| 层次 | 通过依据 |
| --- | --- |
| Skill | 当前会话可读取已安装 SKILL 与相对资源 |
| 离线核心 | 必需 doctor 检查、示例校验、预算试算及 mock 全流程 |
| 连接 | 真实工具发现/schema 与正确权限，不只看到配置存在 |
| 高德业务 | 公开 POI 搜索/详情及路线，核对地点、单位和适用日期 |
| 铁路业务 | 当前日期→可查日期→站码→车次，核对实际起终站和乘车日 |
| 酒店业务 | 两成人一间房的明确日期搜索→一个详情，说明房型、价格和未覆盖字段 |
| 滴滴业务 | 其自身地点检索后一次预估，整车一次计价，不宣称已叫到车 |

逐项记录 `passed / partial / unavailable / not_tested`，不把模拟、工具发现、业务拒绝或发布者历史成功当成真实通过。网站地图的浏览器 JS 接入与 MCP 地图是不同能力，安装默认不测试网站。

在用户私有目录保存简短安装报告：包版本、安装路径、宿主/系统、实际解释器、核心结果、各服务状态、权限范围、私有目录、待人工事项及启动方式。不得包含凭证或真实订单。最后直接告诉用户“离线核心可用”“部分实时服务可用”或“选定实时服务已验收”，并给出一句可复制的使用示例。

## 8. 开始规划与日常使用

用户说“使用 travel-planner，从广州出发，两个人三天，先帮我推荐”时，按 SKILL.md：

1. 提取已知信息，用少量选择题补全当前需要的条件和兴趣；允许不确定，不要求先填完长问卷。
2. 首轮给可比较景点/大致组合、推荐理由和可靠实景或介绍入口。目的地未定先给少量方向；不批量查询所有城市。
3. 需要访问未登录网站时让用户选择登录、公开查询或跳过，用户自行登录；已有 MCP 调用不另加网页登录。
4. 选择方向后细化每日安排，大型景区加入内部入口/景点/接驳/出口、末班、缓冲和备选；用同一活动/路线时间线校验。
5. 收集总预算与已知费用，区分固定/可调项目，按有依据的最低额度与权重试算。金额按分处理，整车费不乘人数，报价、额度、已付和押金分开；不够就显示差额。
6. 结构、硬约束和待核实事项展示后，取得绑定具体变更的真实确认再保存。未知价格不计零，参考日铁路不当目标日核实。
7. 普通 Markdown 已覆盖详细路线和预算。网站在计划确认和明确风格后才显式生成；视觉模板未定稿、不自动发布，真实地图另验收。
8. 修改旧旅行先 read 最新版，再 propose/commit，保留已预订、已支付、锁定和不可变历史；网页导入也只生成候选，不绕过确认。

默认双人、大床房、¥200–300/房晚与华住软偏好需向新用户说明，不是接收方已确认的长期档案。自动挡、早于 22:00 到酒店等规则与日期限定例外按 references/rules.md 处理，不静默放松。健康关怀仅在用户主动提出时启用且只保存必要非敏感结果。

## 9. 更新、回滚与清理

升级先在独立目录校验新包，保留旧 Skill 与本机配置；只移植目标机自己的必要路径/授权，不从发行包取个人配置。验收后切换发现入口，备份放到发现根目录之外，避免同名重复发现。软链接更新只在明确授权的目标上操作，不写入其他项目的源目录。

私有旅行与版本不随 Skill 更新删除，不直接改历史结构；1.2.1 仍读 schema_version=1.0，新增字段可选，未知版本保留并报告。回滚程序版本时先确认能否识别新字段，不能为让旧代码运行而删掉新旅行数据。

完成后关闭本次启动且不需要的进程，删除自己的临时解压/演示/安装候选，保留用户原文件、已安装版本与必要报告。不要清理用户原下载或旧备份，除非得到对应授权。不要为了验收启动长期服务或后台监控。
