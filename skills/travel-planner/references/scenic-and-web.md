# 景区内部路线、地图与网站交付

仅在涉及大型景区细化或最终网站时读取。数据字段与命令见 [数据与命令](data-and-cli.md)。

## 景区内部规划

先根据游览天数、入园入口、出园去向、住宿、体力和必去地点取舍，研究景区官方导览、开放/预约公告与接驳信息。张家界只是应用示例，不将某条线路作为所有旅行的固定答案。

内部每个入口/景点/换乘点建 Place，子地点用 parent_place_id 关联景区；为每次停留建 Activity、每段移动建 Route。活动与路线纳入所属 Day，不能另外放一套未计入时间的内部攻略，也不能把父活动占全天后再重复叠加子活动时间。

scenic_visits 按天组织同一批 activity_ids、route_ids，明确入口、出口、强度、取舍、备用和缩短路线。路线依序接通入口与出口；回到同一入口可使用同一 Place。连续多天游同一景区时每日一组，各自与住宿连接。

Route 的 shuttle/cable_car/elevator/boat 用于景区接驳、索道、电梯及游船，运营资料放 operating_window。depart_at 是计划乘坐/启程时间；排队和到站步行应在此前活动/转场留出，不用理想运行时长掩盖排队。运营证据须覆盖实际游览日期，first_departure_at 可未知，但末班缺失阻止相应景区运营校验通过。票价、排队及开放资料不足保持待核实，不凭地图 POI 推断已开放或已预约。

## 地图数据

- 地点须记录坐标系：gcj02 / wgs84 / unknown。旧记录缺省视为 unknown，不能默认为高德坐标。当前网页只直接绘制明确的 gcj02；其他坐标需在有依据时转换并保留来源。
- 实际 geometry 保存 kind=actual、coordinate_system、按经度纬度排列的 coordinates 与路径来源。只有来源可靠且坐标系正确时展示实线；只有起终点或未知路径时用明确标注的顺序虚线。路径坐标串与起终点明显不符也降级为示意。导航链接不等于真实路径坐标串。
- 编号按日期和当天首次出现顺序，例如 2.3；同一地点重复返回在列表中可复用标点，具体往返仍看各段路线。按日期筛选、点击地点查看介绍；未取得坐标的地点仍在列表显示待核实。
- JS API 的浏览器 Key 与现有 MCP/Web 服务 Key 分开验证。私有地图配置 JSON 仅含 `amap_key`、`service_host`，后者是用户已配置的 HTTPS 安全代理入口，例如 `https://maps.example.com/_AMapService`。示例地址不能当作真实可用代理。安全密钥留在代理服务端，不传入网页或行程；不读取或复制现有凭证。
- 配置文件存在不等于可用；按需点击联网加载后，核实真实底图、标点与路径，缺口明确列出。没有配置或加载失败时保留地点列表与导航，但报告“互动地图未完成”。不为地图另装本机常驻代理。

官方接入说明：[安全密钥](https://developer.amap.com/api/javascript-api-v2/guide/abc/jscode)、[折线](https://developer.amap.com/api/javascript-api-v2/guide/amap-line/poly-line)。

## 确认与视觉方向

需求→初步景点/组合→详细路线和预算→明确确认并保存计划→确认风格→网站。风格可提前以文字或静态参考讨论，具体旅行网站必须等计划确认后再生成。网站不随普通 commit 自动生成。

风格尚未认可，不能默认沿用旧网站。先提供 guide 清爽攻略、journal 旅行杂志、map 地图工具等方向，允许用户描述或提供参考；这三套是可调的起点，不是已经认可的最终审美。`render-web --theme` 必填。浏览器中切换风格仅预览，不代表已经保存风格偏好。

网站来自同一修订的已确认快照，导出检查当前变更的 plan_confirmation，而非只看 can_confirm=true。校验失败、草稿或重新调整中的计划不能生成网站。所有文件保留版本、生成时间与未核实事项；先查看 output-status，不用旧站点冒充最新版。

使用 buildless HTML/CSS/JS，无框架、无需 npm 安装。本地导出可直接打开 index.html，地图需要联网与接入配置。第一版预算只在当前页面试算，明确导出保留；不承诺自动保存、多设备同步或多人协作。

网站的真实数据及导出仍位于仓库外私有目录。不自动公开、上传或发布。需要在线访问时先确定用户希望的访问方式，工具可用时按 Sites 技能进行私有发布并检查实际访问权限；分享链接不应意外公开行程。独立网站、部署配置和私有凭证不混入 skill 的公开示例。

## 网页预算与正式计划

预算额度模型独立于 Quote 和 Expense；同一权重/上下限与整数分算法用于 Python 和网页，通过共享试算样本做一致性检查。已知报价默认保持不变；用户确认允许调整的项目才设 locked=false，最低额度须有真实需求依据，不擅自把住宿/餐饮降为零。权重只分配余额，不保证对应酒店等候选可订。

可调项目先满足 minimum_minor，再按 weight 分配余额，maximum_minor 有限时溢出转给其他项目；没有可调余地时保留未分配余额。固定费用未知就不宣称符合预算；最低所需金额超过预算时显示差额，不给负数额度。备用金 reserve_minor 是项目之外的额外预留，避免和已列 contingency 重复。

每个当前 cost_quote_id（押金除外）都覆盖且只覆盖一次。遗漏的报价会自动补回，不能通过删除行隐去未知费用。匹配的实际已付消费只计一次，未关联报价的净已付消费另加只读项目；押金仍单列资金占用。已预订、锁定、完成或支付的项目由 Python 重新推导保护，网页篡改不能解锁或改价。要补全这类项目的真实报价，走证据/报价更新流程，不通过额度试算冒充。

用户编辑总预算、费用、上下限或权重后页面自动重算，导出“调整草稿”。草稿带原 trip_id、revision、hash 与币种；`budget-import` 核对最新版并产生待审核候选，不直接 commit、不改 Quote、不改支付事实、不自动选酒店。已确认行程回到 detailed；展示影响、用户确认保存后继续核验候选，再确认整份计划、重新生成网站。旧页面或旧草稿必须提示版本冲突，不覆盖新计划。
