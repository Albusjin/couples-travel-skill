# 规则与证据

## 优先级

安全与合法性 → 已预订及已确认约束 → 本次硬性要求 → 预算与时间目标 → 长期软偏好 → 一般排序。同级冲突展示备选，由用户决定；不能通过删除冲突记录使校验通过。

默认情侣 2 人、两人均为计划驾驶人（资格未核验）；缺出发地必须问。自动挡和早于 22:00 到酒店为硬规则。默认一间大床房可按明确单次要求修改；¥200–300/房晚、华住优先、舒适卫生、小众深度体验、步行 5–10 km、顺路当地美食是偏好。早餐、停车、动力类型、座席、车型、固定缓冲分钟数都不是已确认长期要求。

## 三态和确认

`pass` / `violation` / `unknown` 独立于结构错误。草稿可携带规划问题。整份确认必须结构有效、日期已选定、硬规则全部通过，并有具体变更的用户确认。未知价格不阻塞其他规划，需用户接受待核实项后才可确认；仍不宣称完整预算已核实。

缓冲逐段保存标签、分钟数和理由，按道路、时段、排队、停车、交车、补能、天气研究；脚本不凭空生成默认风险参数。没有可靠耗时或适用缓冲依据就保留未知。酒店例外绑定 day ID 与明确日期；`no_hotel` 用于返程回家/用户认可的交通住宿等，`arrival_before` 用于用户明确调整上限。例外不豁免安全、合法性、订单和景点限制。

## 预算

金额以分计，CNY 25000 = ¥250。基础单价 × 数量 + components；components 是整个数量的附加费，不能再乘数量。酒店使用 `room_night`，数量 = 房间数 × 晚数；按人票价数量 = 实际人数。租赁采用供应商明确的实际租期打包价，计费小时/天数及超时条款写入条件和费用构成，不自行假定“跨天=两天”。不同币种不隐式换算。

打车默认两人合乘一辆车，单程费用 `trip × 1`，不乘人数；人均费用才除以二。当前滴滴预估只作参考价，候车/上下车/进站等接驳按实际条件另计时间。铁路目标日未排班可查较早的可查日期参考；保存目标日与参考日，参考班次/票价/余票不得升级为目标日核验结果。操作与数据映射见 [打车与铁路参考规划](transport-planning.md)。

完整费用清单至少核对交通、餐饮、弹性预算；有住宿、活动、自驾或租车时核对相应住宿、门票、租金、油电、高速和停车。免票/无高速等项目可以用有依据的零元或不适用说明，但不能用空值代替零。基础类别之外的强制费用仍须纳入报价 components，研究完成后才能置 `cost_scope_reviewed=true`。模板类别检查不是完整费用审计的替代。

报价 `unknown / queried / rechecked / reference / expired / unavailable` 原样保存；有效状态另行计算。条件不匹配、显式有效期已到 → expired。没有通用 TTL；无明确有效期不代表永久有效，预订前重查。`queried/rechecked` 仍须匹配旅行日期、人数和住宿/车辆条件，提供查询时间和可靠来源；不保证库存。参考/失效价格可显示在“含参考的已知小计”中，不能进入有完整报价证据的小计。押金与预授权独立展示，支付记录不等同于报价。

## 状态与不可逆事实

旅行：draft → researching → proposals_ready → selected → detailed → confirmed → in_progress → completed。允许受控重新研究、取消及回到详细规划。完成状态不重新开放；另建新旅行或更正说明。外部预订状态独立，取消计划不取消订单。

锁定项目的任何变更须确认；已完成对象不能改写。订单状态变化须有新的可靠用户/平台确认，不能重用旧凭证宣称已经取消。已支付/退款记录只能新增更正，不改写旧记录。已有决定不可修改/删除。

## 数据缺失与权限

导航链接与路线耗时是两种证据。真实来源必须记录提供者、查询时间、适用条件和取得的原始入口；不可伪造入口或将模拟源用于验证实际旅行。天气未知时说明预报缺失、出行前核验，并提供不依赖特定天气结论的备选。

脚本对已知敏感字段名作拦截，但无法识别所有自由文本中的隐私；执行本 Skill 的 agent 必须审查保存内容。文件锁与版本哈希处理意外冲突/损坏，不构成身份认证或加密。真实存储私有性、备份和持久化由用户实际宿主环境确认；公开 Git 的忽略规则不能代替提交检查。
