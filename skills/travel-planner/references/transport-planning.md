# 双人打车与铁路参考规划

2026-11-02 用户新增需求：纳入滴滴打车路线，两人只打一辆车；12306 远期未排车次时参考前面几天。此扩展补充 V1 基线，不自动改写已保存的偏好、行程或订单。

## 双人合乘一辆车

- 在市内游玩、火车站到酒店、景点到下一站等段落，比较打车、公交/步行及有意义的租车选项。可提供 `taxi` 和 `rail_taxi` 候选；组合方案逐段保存 rail/taxi 交通，避免一份门到门打包价再重复加接驳费。
- 默认两人同车，`vehicle_count=1`。核对车型的乘客容量、行李空间、经营范围、景区进出/上车点限制；人数或行李改变时重新评估，不能自动拆成两车。这里指两人同乘一辆车，不自动选择与陌生乘客拼车的产品。
- 使用当前可见的滴滴 `maps_textsearch` 按城市检索起终点，核实同名 POI、站点出口和可上车区域。`taxi_estimate` 的 from/to 经度、纬度必须来自地图实际返回；不要猜坐标、互换经纬度或混用坐标系。查询只发公共地点和必要条件，不发送旅客身份资料。
- 当前 `taxi_estimate` 仅接收起终点名称和坐标，没有出发日期/乘客人数参数。两人一车由规划层约束；不得声称 API 已按两人、未来时段预约或保证有车。未返回容量、等待时长或费用时保留未知，不自行补全。
- 用滴滴实际返回的车型、预估费用、时长及入口；字段缺失时用高德核实道路耗时，并说明来源。当前预估价不是未来锁价，记录查询时间与 `pricing_basis="current_estimate"`，Quote 用 `reference`。高德道路耗时不代表滴滴实时接单或候车时间。
- 预算按**一辆车、一个单程**计费：`category="transport"`、`unit="trip"`、`quantity=1`。例如整车预估 ¥40，双人合计 ¥40，人均 ¥20；不是 ¥80。往返分别建段、分别查询，不盲目翻倍；多个车型互为候选，不全加进总预算。
- 核对远途、跨城、高速、停车、候车、夜间、动态调价等是否包含在返回总价内。已包含的费用不再加 components；未知费用不按零。区间价保持区间说明，不能把最低价当成完整总价。
- 门到门时间包含走到上车点、候车、道路行程、下车与必要步行，保存适用 buffers 及理由。赶高铁还需进站/安检/候车；两端都有接驳时分别计算。22:00 酒店规则仍适用；关键时长未知时只给估算与备选，不宣称硬约束通过。
- 此 Skill 只查询和规划。可展示工具真实返回的叫车入口供用户操作；不自动发单、支付或取消，不将“取得预估”标成 booked。

## 12306 目标日期缺数据时

1. 解析目标日期，保留用户真正的出行日期和站点/时段/席别。相对日期按 12306 工具要求先取当前上海日期；必要时核对具体车站，保留车站名与 code，避免城市代码混淆。
2. 先用 `get_tickets` 查询目标日，按需求筛高铁/动车、时段，限制返回条数。区分未起售/未排班、空结果、无余票、筛选过窄、网络错误；这些不是同一事实。已返回车次但售罄时保留真实车次和无票状态，参考日余票不能覆盖它。
3. 目标日未起售/未排班，或在核对筛选后仍为空时，可参考**早于目标日且当前工具实际支持查询**的日期。默认先查接近目标日的可查日期；有多个可用日时优先同星期/相似时段，必要时再核对 1–2 天，串行小批查询。不要不断请求仍超范围的“目标日前一天”，也不盲目查工具不支持的过去日期。不把预售期写死为永久常数。
4. 空结果原因未明时 reason=`target_empty`，说明“目标日暂未返回，原因待核实”，不擅称停运/未开售。只有工具或官方证据明确时才用 `not_on_sale` / `schedule_unpublished`。纯网络错误先有限重试或说明不可用；不能伪装成未排车次。不得伪造历史数据。
5. 同一站对、相近时段的参考日车次可用于估算旅行方向、运行时长、参考票价及接驳范围。记录查询时间、参考出发/到达日期（含跨夜）、车站、车次、席别、运行时间和原始来源。保留多日差异，说明周末、节假日、调图、临客及季节差异，不能把它们平均成一个“确定时刻”。
6. 输出“目标日 X 尚待核实；参考日 Y 的班次/时刻/票价，仅供规划”。目标日余票保持未知，不移植参考日的“有票”、放票时间、库存和库存数量。参考票价按两张人票计入已知参考小计，不纳入完整已核实总价。铁路可提供参考方向，继续比较打车/自驾/租车，避免停在无数据。
7. 参考时刻只能生成估算路线或时间范围。标记需目标日复核的车次、发到时刻、票价、席别、余票及接驳；目标日尚未核实前不能用参考路线证明赶车/中转/酒店到达硬约束。用户可以选方向、保留草稿，不据此提升整份计划至 confirmed。
8. 用户后续要求复核或实际可查时重查目标日，比较交通、打车接驳、酒店和预算影响；用目标日真实证据替换参考标记并重新校验。修改已锁定项按既有变更确认流程处理；不创建未授权的后台监控。

## 数据映射

兼容现有 `schema_version="1.0"`：新增枚举值和可选字段，不要求重写历史文档；新字段出现时必须满足其契约。

| 对象 | 保存方式 |
| --- | --- |
| Proposal / request.transport_preferences | 支持 `taxi`、`rail_taxi`；Transport 仍按具体 rail/taxi 单段记录 |
| taxi Transport | `mode="taxi"`；可选 `taxi_details={"passengers":2,"vehicle_count":1,"service_name":"实际返回车型名称","passenger_capacity":null}`；容量未知保留 null |
| taxi Route | `mode="taxi"`；transport_id 关联该交通，source_ids 指向实际时长证据，buffers 保存适用候车/步行等；道路可验证不代表接单保证 |
| taxi Quote | 关联 Transport，单程 `trip × 1`；conditions/expected_conditions 均保留 trip_start/trip_end/travelers，以及 passengers/vehicle_count/from_place_id/to_place_id/depart_at；当前预估附 pricing_basis=current_estimate，status=reference |
| 铁路参考 Transport | `rail_reference={"target_date":"2030-05-10","reference_date":"2030-05-03","reason":"schedule_unpublished"}`；depart_at/arrive_at 如填写，是明确标注的目标日假设时间，不是已确认时刻 |
| 铁路参考 SourceRecord | kind=reference；conditions 保留 target_date、reference_date、站对/时段/席别；note 保留实际参考日发到时刻和差异。参考日来自官方工具也不升级为目标日证据 |
| 铁路参考 Route / Quote | Route.evidence=estimated；Quote.status=reference，按人票数量计；通过 transport_id / quote_ids 关联参考交通。即使误写 verified/queried，校验与预算也不得提高其证据等级 |
| 目标日复核成功 | 取得实际目标日证据后移除 rail_reference，更新关联路线、报价和来源，按既有版本/锁定规则提交；只改标签不代表复核成功 |

`query taxi` 沿用 ProvidedDataAdapter，只封装用户提供或模拟响应；真实滴滴查询由 Codex 使用 MCP，不宣称 Python CLI 自己调用了供应商。
