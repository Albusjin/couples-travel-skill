# Couples Travel Skill · 情侣自由行规划

让 AI agent 帮两个人把一个粗略的旅行想法，逐步变成有来源、能调整、可确认的行程。

**通用版 1.2.0 · 2026-11-03**。面向中国大陆双人自由行，包含完整 Skill、轻量 Python 核心、Codex / DeepSeek Harness 配置参考和 Agent 安装规范。接收方下载后把安装交给自己的 agent；模型、账号与服务授权由接收方环境提供。

## 下载并交给你的 Agent

**[下载通用 Skill ZIP](https://github.com/Albusjin/couples-travel-skill/raw/refs/heads/main/releases/travel-planner-universal-1.2.0.zip)** · [SHA-256 校验值](releases/SHA256SUMS) · [更新日志](CHANGELOG.md)

1. 下载并解压，得到完整的 `travel-planner/` 文件夹。
2. 用能读写文件、运行命令的 agent 打开这个文件夹。实时查询还需要宿主支持 MCP / 网页工具。
3. 复制下面这段话给 agent：

> 请先阅读这个 travel-planner 目录里的 AGENT_HANDOFF.md，按里面的规范完成安装、运行环境配置与分层验收。请根据我的电脑和当前 agent 应用选择合适路径，优先复用已有 Python、依赖与 MCP 连接；不要覆盖其他设置或旅行数据。只有宿主无法确定、私有数据存储位置未确认或缺少必要授权时再向我收集信息。凭证由我在本机安全输入，不让我在聊天里粘贴。先完成离线核心，再接通我需要的实时服务；最后报告哪些功能可用、哪些待配置，并告诉我如何开始使用。安装阶段不生成或发布旅行网站。

也可以下载整个 GitHub 源码包：此时 Skill 根目录是 `skills/travel-planner/`。**不要把整个仓库当成一个 Skill 安装。**

## 它怎样帮你规划

| 环节 | 使用体验 |
| --- | --- |
| 补全粗略想法 | 用少量选择题收集日期、天数、预算、交通、体力和兴趣；已知信息不重复问，可选“不确定，帮我推荐” |
| 首轮推荐 | 给多个景点、推荐理由、建议时长、实景照片或介绍链接，再比较大致路线；目的地未定时先比较方向 |
| 查询网站 | 需要访问未登录的网站时让用户选登录、公开查询或跳过；登录由用户完成 |
| 景区内部路线 | 不止写“去张家界”，还细化园内入口、景点顺序、步行/接驳/索道、末班和缩短路线 |
| 交通住宿比较 | 比较高铁、自驾、租车、两人一辆车的打车及组合；核对门到门时间、房晚、取还车与费用 |
| 预算调整 | 输入双人总预算和已知票价、租金等，按最低/最高额度与权重分配其他支出；不足显示差额，试算不篡改报价 |
| 确认与修改 | 先比较再选定、细化、确认；保存不可变版本，保护已预订/已支付项目，修改某天会检查关联影响 |
| 输出 | Markdown 攻略、预算表和路线索引；保留确认后网站及地图功能基础，但视觉设计尚未定稿 |

地图功能需要可靠地点坐标、正确坐标系和实际路径来源。网页地图还需单独的 JS API 配置与实际加载验证；地点列表不等于完整互动地图。网站必须在具体计划确认、风格选择后显式生成，普通保存不会自动生成或发布网站。

## 安装后直接这样说

**只有大致想法：**

> 使用 travel-planner。我们从广州出发，想找个三天左右的地方放松，目的地还没定。用选择题了解我们的偏好，先给几个方向和景点让我选。

**需要景区内部路线：**

> 使用 travel-planner 帮我们规划张家界。除了每天去哪，还要细化森林公园内部路线，说明入口、景点顺序、索道与接驳、体力和备选路线。时间预算先问我。

**需要自动分配预算：**

> 双人总预算 6000 元，车票合计 1200 元、租车合计 800 元，这两项先保持不变。帮我分配剩余住宿、餐饮和可选体验，说明你需要的最低额度与取舍。先不做网站。

**调整已经确认的计划：**

> 读取上次旅行，把第二天改得轻松一点，先告诉我对费用、住宿和第三天起点有什么影响。

费用统一区分单人价、双人价、整车价、房晚及租期。两人合乘一辆车只计一次整车费；未知费用保留未知，远期铁路参考日结果不当目标日事实。

## 适用环境与默认规则

- **Python 3.11+**；核心依赖只有 `jsonschema` 和 `tzdata`。优先复用可用环境，缺少时由 agent 创建隔离环境。
- Windows、macOS、Linux 共用业务代码；本地铁路 MCP 才需要 Node/npm，地图等 HTTP 连接不要求另装本地 Node 服务。
- Codex 提供 TOML 模板；DeepSeek Harness 提供 Cordis YAML 参考。其他 agent 按其官方发现/执行/MCP 机制适配，没有通用的跨应用配置语法。
- 默认两人、一间大床房，酒店 ¥200–300/房晚及华住为软偏好，不是接收方已确认的长期档案；首次使用可以说明自己的偏好。
- 自动挡、每天含缓冲到酒店早于 22:00 等既有规则与明确例外机制见 [规则](skills/travel-planner/references/rules.md)。

离线规划、预算和版本管理不需要旅游账号。实时地图、铁路、酒店、打车的授权、网络和返回字段必须在接收方电脑分别验收；缺少一项可继续其他工作。普通网页聊天若没有文件执行能力，只能讨论，不能完成本地安装。

本 Skill 不执行预订、支付、叫车、取消订单、定位跟踪或后台盯价。网站模板不是独立手机应用，也不提供多人同步、自动云保存或承诺实时库存。

## 数据与安装边界

ZIP 不含发布者的 Key、私人路径、真实旅行、登录状态、虚拟环境或预装依赖。真实旅行、偏好、草稿、导出与安装报告仅保存到用户确认的安装包和 Git 仓库外私有目录。MCP 模板默认停用；只合并所需服务，不替换整份宿主配置。

安装、核心可运行、工具可发现、真实业务查询成功是四件不同的事。Agent 应逐项说明结果，不以发布者的历史记录代替目标机验证。详细步骤和失败分支都在 [Agent 交接文档](skills/travel-planner/AGENT_HANDOFF.md)。

## 开发与重新打包

下面的 `python` 指已具备依赖的 Python 3.11+；Windows 可使用实际解释器或 `py -3`。从仓库根目录运行：

```sh
python -m unittest discover -s tests -v
python scripts/build_release.py
```

构建使用 [明确的发行白名单](release-files.json)，拒绝符号链接、私人配置、过大文件和可识别凭证，生成小型确定性 ZIP、逐文件 `MANIFEST.json` 和 `SHA256SUMS`。校验清单用于一致性检查，不是数字签名或完整秘密审计。

发行包版本为 **1.2.0**，旅行数据仍为 `schema_version=1.0`，本次新增可选字段兼容旧文档；不自动改写已有旅行历史。远端 CI 与目标机实际验收结果分别报告。
