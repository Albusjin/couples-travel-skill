# Travel Planner V1.0 详细设计与决定

日期：2026-11-01。正式基线为 [PRD](Travel-Planner-PRD-v1.0.md)，[实施笔记](implementation-notes-v1.md) 不修改基线。本文件记录用户确认的实施选择，不改写原文。

## 交付与边界

交付 `skills/travel-planner` 自包含安装包：SKILL.md、规则/数据说明、JSON Schema、Python 3.11+ 核心、Markdown 模板及虚构演示。自然语言解析、目的地研究、推荐与安全判断由 Codex 按 Skill 执行；这是 Agent Skill，不是独立的旅游搜索服务。

首轮仅核心闭环及透明降级。P1 专项能力、Word/PDF/手机执行版、V2 网站、持续监控与交易不作为完成前提。不绑定供应商、不要求读取账号凭证，不把模拟报价用于证明真实查询能力。

## 已确认决定

| 问题 | 实施决定 |
| --- | --- |
| 首轮范围 | 核心闭环、确定性脚本、Markdown、模拟验收；真实工具单独验证 |
| 确认门槛 | 硬约束须全部通过；未知价格可经用户明确接受后确认，仍不声称完整总价已核实 |
| 跨夜及无需酒店 | 不自动豁免；按具体日期逐次确认例外，保留安全与已预订约束 |

| 局部修改 | 保持其他天；必要时先展示并确认扩大范围，锁定项另行确认 |

## 架构与接口

自然语言 → TripRequest/候选实体 → schema 与引用检查 → 三态规则和预算 → 候选 ChangeSet/影响报告 → 用户必要确认 → 不可变修订 → 同版本视图。

- JSON Schema 2020-12 定义 Trip、TravelProfile 及实体；稳定 ID 关联。金额为整数分、币种分隔计算；标准库强制校验真实日期、带偏移时间、HTTP(S) 入口，避免 jsonschema 可选格式依赖缺失时漏检。
- Trip 与 Profile 独立，创建旅行时复制已确认偏好快照，PRD 默认值不自动保存为新档案。单次覆盖只写请求。报价、订单、支付、选择及锁定分别记录。
- CLI 提供 init/read/validate/propose/commit/compare/restore/render/output-status 及 profile/query 命令。统一 JSON 错误；结构/引用/事务错误禁止保存，规划问题允许草稿；确认、执行和完成受硬约束门槛约束。
- CapabilityRequest/Result 及 Adapter 协议隔离供应商。当前仅用户提供资料/模拟适配器；失败返回 unavailable/partial，不自动提升记录的证据等级。
- SourceRecord、Quote 状态和费用完整性共同决定报价证据。按实际日期、人数、房型/车型条件及明确有效期判断；不发明统一 TTL。报价无条件、来源、完整强制费用或费用类别覆盖时保持待核实。全部金额未知时小计为 null，不显示为零。
- 路线耗时、导航、缓冲独立记录。按时间排序验证逐日地点连续、时间冲突、日期覆盖、跨日起终点和酒店返程。纯电路线提供基础里程/余量计算，不能替代实际路况、能耗及充电服务核验。

## 事务、恢复与隐私

每个旅行/档案独立目录，HEAD 指向包含 document/change 的不可变修订 bundle，并保存哈希。propose 绑定原 revision/文档哈希与候选哈希；commit 在独占写锁下重查，保存快照成功后原子替换 HEAD。旧快照和旧输出不覆盖。

影响分析对新旧实体引用求依赖闭包，输出受影响对象及日期。仅因修改住宿/来源/报价就影响多日时，同样要明确展示；计算总预算不意味着可直接更改其他天安排。确认记录绑定 change_id；跨夜例外可先在对话确认，再记录日期限定的 Decision。

锁定对象修改须确认，已完成对象、已付/退款记录及已有决定不可改写。预订状态提升需要可靠来源；已预订事实变更需要新的用户/平台确认。恢复仅取历史规划内容，不撤回当前订单、支出及确认事实；结构不兼容或触及不可改写历史时拒绝并保留原计划。

写入中断可留孤立快照；后续修订跳号，不复用编号。输出采用暂存目录完成后整体发布；输出失败不撤销已提交的数据，新旧版本状态通过 output-status 区分。锁残留只在确认无活跃写入后手工清理。未知模型版本保留、拒写；V1.0 尚无需要迁移的旧数据模型，后续显式迁移必须保留原件并生成新修订。

数据根目录显式指定并拒绝位于 Git 仓库中，子路径检查符号链接越界；新目录使用 0700、新 JSON 文件使用 0600（操作系统权限语义允许时）。脚本不是加密或身份认证方案，也不能验证云存储私有性。已知敏感字段拦截仅为辅助；自由文本必须由 Agent 审查，普通档案只记录非敏感活动调整结果。恢复和文件校验针对单机协作、意外冲突/故障，不防御拥有相同文件权限的恶意进程。
