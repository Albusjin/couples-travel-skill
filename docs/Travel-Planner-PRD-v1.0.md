# Travel Planner Skill 产品需求基线 V1.0

> 整理日期：2026-11-01  
> 状态：基于用户多轮确认重建的需求基线；不是已实现功能清单。  
> 来源：[“询问内置MCP能力”对话](chatgpt-conversation://6ae6f7fa-4fac-83ee-b023-b1e3497f7838)中的四轮用户输入。原对话的助手回复正文在当前读取接口中仅返回引用标记，无法逐字核对；本文件并非该回复的逐字副本。以下明确区分用户确认、建议设计和待验证事项。

## 1. 目标与范围

**已确认**：为主要由两人组成的情侣出行提供中国大陆城市游、周末游、多城市长途游、自驾游或租车游规划。兼顾预算与性价比、减少交通时间和折返、小众景点与深度体验、自由灵活；先比较方案，再细化，并支持旅途中重规划。支持固定日期与尚不确定日期的规划；每次询问或接收出发地，缺失时询问。

查询、比较并提供可用的预订入口；不将推荐或查询描述为预订成功。遇到约束冲突时给出备选，由用户决定。暂不选择或安装具体 MCP。

## 2. 已确认偏好与约束

| 类别 | 基线 |
| --- | --- |
| 人员与房型 | 主要两人，同住一间普通双人大床房。 |
| 酒店 | 舒适度优先；每晚 200–300 元优先，可提供更高价备选并说明差额；华住会旗下品牌优先，其他品牌可作为更优备选。 |
| 交通 | 高铁、自驾、租车；一般以租车为主。适用时比较全程自驾与高铁后租车。 |
| 租车 | 仅推荐自动挡；结合价格、舒适空间与安全推荐平价车型及规格；两人都可驾驶，可考虑异地还车。车辆类型不固定。 |
| 驾驶与补能 | 每日驾驶时长灵活；可以夜间驾驶，但应在 22:00 前抵达酒店。根据车辆续航和安全余量规划加油或充电。 |
| 节奏 | 关键环节时间精确，其余保持灵活并预留自由活动；步行量一般为每日 5–10 公里，按具体行程调整。 |
| 餐饮和活动 | 顺路特色餐饮；无饮食禁忌。偶尔爬山徒步或去海边，按计划建议装备。 |
| 预算与价格 | 超预算时提供备选；价格缺失时继续规划并标记待核实。数据不完整时只把已验证信息当作事实，明确缺失。 |
| 修改与保存 | 已确认内容锁定，修改时优先局部调整；偏好逐项确认后才持久保存或更新。 |
| 健康 | 仅在用户主动提及时启用相关关怀。按用户提供的实际情况调整活动或先提醒询问；例如生理期可提醒卫生用品，并就游泳、冷饮等询问偏好，不作一刀切的医学判断。 |
| 输出 | 对话中详细攻略、每日地图路线、交通/酒店/预算对比表；Word、PDF 和手机精简版按需导出。 |
| 后续网站 | 最终方案未来可考虑部署为私有双人移动端查看，修改后同步更新；属于后续增强。 |

偏好是可修改的默认值，不代表每次都无需确认具体日期、预算或约束。

## 3. V1 功能要求

1. **收集输入**：获取目的地或大致计划、出发地、固定或灵活日期；缺失的关键条件先询问。收集本次预算、交通、驾车、房型及活动约束；对未提供信息标记待确认，不凭空补全。
2. **方案比较**：先提供可比较的行程与交通方案，适用时比较全程自驾与高铁后租车，说明时间、预算、舒适度、折返及不确定性；用户选定后细化。
3. **逐日路线**：按地理顺序安排景点、餐饮、交通、住宿及自由活动，检查关键时间、交通衔接、步行与 22:00 前到酒店约束。地图路线按可用工具生成；不可生成时给出有序地点与待核实项。
4. **酒店与租车**：按第 2 节偏好比较，展示来源与可得的关键条款；异地还车、第二驾驶人资格和费用须单独核实。车型展示已核实的自动挡、座位/空间、能源类型、续航或油耗等相关规格；未知项明确标注，不将示例车型等同于实时车源。
5. **补能与安全余量**：基于车辆类型、可用续航、路段和安全余量提出补能节点；站点可用性、营业和实时状态未验证时标记待核实。不设未经确认的固定续航余量或驾驶时长。
6. **预算与透明度**：按交通、租车、能源、住宿、门票、餐饮等可得项目列出费用、人数/间数、日期、币种及是否包含税费；区分实时已核验报价、估算、缺失和可能额外收费。展示来源与查询时间；条件不充分时不计算看似确定的总价。超预算给出差额及备选。
7. **预订与确认**：提供可用入口，不自动支付或代为预订；只有用户明确确认后才记录已确认或已预订状态。保留确认内容，重规划时说明影响并征求用户对冲突变更的决定。
8. **异常与重规划**：对价格缺失、无房/无车、开放时间或交通不可核实、天气变化、路线不可达、超预算和时间冲突提出待核实事项及备选；对已锁定内容仅在用户同意后调整。
9. **输出**：先在对话展示方案与详细攻略；按需提供可用的地图、比较表、可打印 Word/PDF 和手机精简版。输出能力取决于实际环境与工具，不假定全部可用。

## 4. 输入与输出契约

### 输入

| 项 | 要求 |
| --- | --- |
| 出发地 | 每次指定；缺失时询问。 |
| 目的地或计划 | 用户给出目的地、意向区域或大致计划；不足以形成路线时询问。 |
| 时间 | 固定日期或灵活日期/范围；必要时补充天数及时间边界。 |
| 人数、住宿、交通、预算 | 使用已确认偏好作为默认参考，收集本次不同之处；缺失的必要信息询问。 |
| 其他 | 目的、体力、车辆与补能、活动、已预订项、需要的交付形式；敏感健康信息仅由用户主动提供。 |

### 输出

- 方案比较：路线、交通方式、时间、费用范围或待核实项、优势及限制。
- 选定方案后的逐日安排：地点顺序、关键时刻、交通与预计耗时、住宿、餐饮、自由时间、步行量及补能提示。
- 酒店、交通、租车、预算比较：报价状态、来源、查询时间、条件、潜在额外费用、预订入口和缺失项。
- 实用信息：装备清单、风险及替代方案、明确标注的待核实事项；按需输出地图、Word、PDF 或手机精简版。
- 所有时间、费用和可用性均应区分已核实、估算与未知；不得将未验证信息写成事实。

## 5. 数据模型（建议设计，尚待实现验证）

以下是实现与测试所需的最小逻辑字段，不指定存储技术或具体接口。可为未知值留空并附原因，避免把推测当成数据。

| 实体 | 建议字段 |
| --- | --- |
| Trip | 标识、目的地/主题、出发地、日期类型与范围、人数、预算及币种、偏好快照、总体状态、版本、更新时间。 |
| Preference | 类别、值、适用范围、用户确认状态和时间；健康信息单独处理。 |
| Option | 方案标识、路线、交通组合、预计时长、费用范围、优缺点、来源、未确定项、选择状态。 |
| Day / Activity | 日期或相对天数、有序地点、类别、起止或时间窗口、预计耗时/步行、预订关联、锁定状态、来源与待核实项。 |
| Transport / Vehicle / Energy | 方式、起终点、班次或取还车时间地点、车型及已验证规格、驾驶人/异地还车条款、预计续航和补能节点。 |
| Lodging / Dining | 名称、位置、日期、房型或餐饮类型、价格与条件、来源、可用性和确认状态。 |
| Quote | 金额或范围、币种、单位与人数/间数、日期、包含与不包含项、状态、来源链接、查询时间、有效条件及缺失原因。 |
| Booking | 关联项目、用户提供或确认的预订状态、关键时间地点、锁定状态；仅在确有需要时存储最少必要信息。 |
| Issue / Alternative | 约束冲突或缺失、影响范围、候选替代方案、用户决定、处理状态。 |
| Export / Version | 导出类型、所依据的行程版本、生成时间、同步状态；不默认生成或公开。 |

## 6. 状态机（建议设计）

- **行程**：收集信息 → 方案比较 → 用户选定 → 细化中 → 用户确认 → 出行中 → 已完成；可从细化、确认或出行中进入重规划，再返回相应阶段。
- **单项**：候选 → 用户确认并锁定；如用户实际完成预订，可记录已预订。变更已锁定或已预订项前，展示影响并取得用户决定。若外部状态无法核验，记录其来源和不确定性。
- **报价**：已核实、估算、待核实、已过期/不可用；每次展示适用条件和查询时间，避免旧报价被误当作当前报价。
- 以上是实现建议，不意味着预订或实时状态查询已接通。对话确认、实际预订和支付是不同事件。

## 7. 隐私与权限

- 默认不公开个人行程、行踪、证件、订单或健康信息；本公开仓库只存放通用需求和代码，不放真实旅行记录或凭证。
- 偏好仅在逐项获得确认后持久保存或更新；健康关怀仅在用户主动提及时用于本次相关规划，持久保存需单独确认。
- 查询和导出只使用完成任务所需的最少信息；预订入口的第三方条款和数据处理以实际服务为准。
- 私有双人网站是后续设想，需在建设前设计身份验证、双人访问控制、存储、同步及撤销访问；不能把“私有”视为已经实现。

## 8. 验收标准

1. 缺少出发地时询问；固定和灵活日期均能进入规划，无法确定的条件标记待确认。
2. 在适用行程中先比较全程自驾与高铁后租车，再按用户选择细化；涉及未知条件时明确说明。
3. 默认两人一间普通大床房；优先比较 200–300 元及华住会选项，同时允许说明更优其他品牌和超预算备选。
4. 租车推荐只含已核实自动挡车型；第二驾驶人、异地还车、额外费用及补能信息不确定时标记待核实。
5. 逐日行程能检查 22:00 前到酒店、关键衔接、路线顺序及步行量；冲突提供替代并由用户决定。
6. 价格缺失不阻断其余规划；每项区分已核实、估算或待核实，并展示可得来源、条件与查询时间。
7. 更改局部行程时保留已锁定项目；影响锁定项时先展示影响并取得用户决定；不把推荐当作预订。
8. 用户未主动提及健康情况时不启用健康关怀；未经逐项确认不持久保存或更新偏好。
9. 对话输出方案及必要的待核实项；地图、Word、PDF、手机精简版按需提供，工具不支持时明确说明。

## 9. 未来升级与工具能力待验证

**后续增强**：私有双人移动端站点、行程修改后的同步、实时状态与更丰富的地图交互；具体范围和优先级待确认。

**真实环境需验证**：数据来源及覆盖范围、地图路线输出、景点/营业信息、交通与酒店/租车实时价格和库存、自动挡及车型规格、第二驾驶人和异地还车条款、补能站状态、预订入口、Word/PDF 导出，以及偏好保存和私有双人访问能力。未验证前不得声称具备相应实时查询、预订、同步或安全保障。

本基线不选择、不安装具体 MCP，也不承诺外部服务可用性。
